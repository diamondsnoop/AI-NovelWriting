# V0.5.0 审查设计冻结页（HighPoint / ReaderPull / Gatekeeper）

## 0. 目的与冻结范围

本页用于冻结 `V0.5.0` 审查层设计，确保结构开发期间不再反复讨论方案。

冻结对象仅限以下 4 项：

1. 输入字段口径
2. 触发条件
3. 输出信号
4. gatekeeper 分级规则

冻结生效后：

- 结构开发阶段不改字段名、不改触发链路、不改信号语义、不改分级逻辑。
- API 恢复后仅允许做“提示词与阈值微调”，不改设计框架。

---

## 1. 输入字段口径（冻结）

## 1.1 通用输入（来自 `review.service_v2 -> checker`）

- `draft_text`: 当前章正文草稿
- `chapter_no`: 当前章号
- `write_package.chapter_outline`
- `write_package.chapter_beats`
- `write_package.chapter_timeline`
- `write_package.volume_plan`
- `write_package.previous_summary`
- `write_package.retrieved_context`
- `write_package.project_state.progress`

## 1.2 HighPoint Checker 专用输入

- `structured_summary.key_events`（当前章）
- `structured_summary.main_plot_advanced`（当前章）
- `structured_summary.high_point_markers`（当前章，V0.4 已预埋）
- `chapter_beats`（当前章节拍表）
- `chapter_timeline`（当前章时间线）

字段解释（冻结）：

- `high_point_markers` 定义为“强情节/爽点节点列表”，类型固定为 `list[str]`。
- 若模型未给出，按空数组处理，不做字段回退改名。

## 1.3 ReaderPull Checker 专用输入

- `structured_summary.reader_pull_marker`（当前章，V0.4 已预埋）
- `draft_text` 尾段窗口（最后 15% 文本，最少 300 字，最多 1200 字）
- `chapter_outline` 的结尾钩子描述
- `chapter_beats` 的最后一个节拍

字段解释（冻结）：

- `reader_pull_marker` 结构固定为：
  - `has_pull: bool`
  - `pull_type: str`
  - `evidence: str`
- 该对象缺失时按默认值：
  - `has_pull=false, pull_type="", evidence=""`

## 2. 触发条件（冻结）

## 2.1 审查主链触发

在 `workflow.write_flow` 中，`ReviewService.review_draft` 被调用时统一触发：

- `high_point_checker`
- `reader_pull_checker`

两者都属于 `review` 内部 checker，不允许由 `workflow` 直接调用子 checker。

## 2.2 Checker 级触发

`high_point_checker` 触发条件：

- `draft_text` 非空
- 章号 `chapter_no >= 1`
- 若 `chapter_beats`、`high_point_markers` 都为空，则返回 `skipped`（不报错）

`reader_pull_checker` 触发条件：

- `draft_text` 非空
- 章号 `chapter_no >= 1`
- 若尾段窗口提取失败，返回 `skipped`

## 2.3 与 Decision 的边界

- checker 不直接触发 `decision`。
- checker 只返回结果和信号。
- 是否进入 `decision` 仍由 `workflow` 决定。

---

## 3. 输出信号（冻结）

## 3.1 Checker 输出结构

`high_point_checker` 与 `reader_pull_checker` 对外返回统一结构：

- `checker: str`
- `status: completed | skipped`
- `score: float | None`（范围 0~1）
- `severity: critical | warning | info`
- `issues: list[str]`
- `message: str`
- `signals: { codes: list[str], metrics: dict }`

说明：

- `signals.codes` 是标准化信号码，供 gatekeeper 分级消费。
- `signals.metrics` 是计数或比例，用于报告展示，不直接决定流程。

## 3.2 HighPoint 标准信号码（冻结）

- `high_point_missing`
- `high_point_density_low`
- `high_point_not_aligned_with_beats`
- `high_point_present`

## 3.3 ReaderPull 标准信号码（冻结）

- `reader_pull_missing`
- `reader_pull_soft_landing`
- `reader_pull_weak_hook`
- `reader_pull_present`

## 3.4 信号与严重级的映射（冻结）

HighPoint：

- `high_point_missing` -> `critical`
- `high_point_density_low` -> `warning`
- `high_point_not_aligned_with_beats` -> `warning`
- `high_point_present` -> `info`

ReaderPull：

- `reader_pull_missing` -> `critical`
- `reader_pull_soft_landing` -> `warning`
- `reader_pull_weak_hook` -> `warning`
- `reader_pull_present` -> `info`

## 4. Gatekeeper 分级规则（冻结）

## 4.1 Gatekeeper 输出结构

`gatekeeper` 在现有 `gate_result` 基础上，增加固定字段：

- `gate_result: blocked | pass`
- `gate_level: critical | warning | info`
- `blocking_reasons: list[str]`
- `warning_reasons: list[str]`

兼容性要求：

- `gate_result` 继续保留，避免破坏现有调用链。
- 新字段用于分级展示和后续策略升级。

## 4.2 分级判定规则

`blocked`（必须拦截）：

- 仅当“阻断型 checker”命中 `severity=critical`
- 或核心一致性链（`consistency/character/continuity`）命中既有硬阈值拦截规则

阻断型 checker（冻结）：

- `consistency`
- `character`
- `continuity`

非阻断型 checker（冻结）：

- `high_point`
- `reader_pull`
- `foreshadowing`

说明（冻结）：

- `high_point` / `reader_pull` 即使返回 `severity=critical`，在 `V0.5` 阶段也不直接触发 `blocked`。
- 这类 `critical` 统一进入 `warning_reasons`，用于“强告警、不中断”。
- 等 API 恢复并完成误报率/稳定性评估后，再决定是否升级为阻断型。

`pass + warning`（可继续，需告警）：

- 无 `critical`
- 至少一个 checker `severity=warning`

补充（冻结）：

- 若仅非阻断型 checker 命中 `severity=critical`，也归入 `pass + warning`。

`pass + info`（可继续，仅报告）：

- 所有 checker 仅 `info` 或 `skipped`

## 4.3 Score 阈值规则（冻结）

用于将分数映射到严重级：

- `score < 0.35` -> `critical`
- `0.35 <= score < 0.6` -> `warning`
- `score >= 0.6` -> `info`
- `score is None` 且 `status=skipped` -> 不参与分级

---

## 5. API 恢复后允许调整范围（不破冻结）

允许调整：

- checker 提示词
- 规则阈值（如 0.35/0.6）
- metrics 计算细节

不允许调整：

- 字段名与字段结构
- 标准信号码
- `workflow -> review -> gatekeeper` 调用链方向
- gatekeeper 分级机制（blocked / pass+warning / pass+info）

---

## 6. 一句话结论

`V0.5.0` 的审查设计已冻结：结构开发可直接按本页实现，API 恢复后仅做质量校准，不再改框架。
