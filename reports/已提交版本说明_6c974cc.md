# 已提交版本说明（6c974cc）

这份说明对应已推送到远端仓库的基线版本：

- 提交号：`6c974cc`
- 提交信息：`Baseline before entity extraction JSON`

## 1. 这个版本已经完成了什么功能

### 1. 项目初始化
- 可以创建一部小说项目的基础目录和运行状态文件。
- 会生成章节、摘要、大纲、任务状态等后续流程所需的基础结构。

### 2. 章节规划
- 可以为指定章节生成大纲。
- 每章会同时生成两份大纲：
  - 完整版：给人看，保留完整规划信息
  - 精简版：给写作流程用，只保留章节目标、关键节拍和结尾钩子

### 3. 章节写作
- 可以基于当前项目状态和章节大纲生成章节草稿。
- 写作流程已经接入真实模型调用链。
- 经过精简版大纲组包后，真实 API 已能稳定跑通写作主链路。

### 4. 写后回写
- 写完章节后，会继续生成：
  - 文本摘要
  - 结构化摘要
- 这些内容会落盘，供后续章节和查询功能使用。

### 5. 基础审查
- 已接入多维审查框架。
- 当前真实可工作的审查维度主要包括：
  - 连贯性
  - 一致性
  - 人设检查
  - 节奏检查
- 其中连贯性已经完成真实验证；其余维度在这个版本中已接线，但依赖的数据基础还在继续补强。

### 6. 决策交互
- 已实现第一个真实决策场景：
  - 当用户重复写同一章时，系统会判断是覆盖还是中止
- 这说明“系统遇到关键分歧时停下来问用户”这条机制已经接进主链路。

### 7. 恢复与查询
- 可以查看最近任务状态和快照。
- 可以查询项目信息、进度、任务、快照、决策记录、摘要等内容。

## 2. 这些功能分别由哪些模块完成

### 初始化
- `workflow.init_flow`
  - 负责启动初始化流程
- `memory.store`
  - 负责创建项目状态和目录结构

通俗比喻：
像给一本新书建档、开文件柜、贴标签。

### 章节规划
- `creation.outline_engine`
  - 负责生成章节大纲
- `workflow.plan_flow`
  - 负责保存完整版和精简版大纲
- `memory.store`
  - 负责大纲文件的路径管理

通俗比喻：
像编剧会先写一份完整分场，再额外写一张“拍摄任务单”给导演。

### 章节写作
- `workflow.context_package`
  - 负责组装写作上下文包
- `creation.writer_engine`
  - 负责发起正文生成
- `foundation.agent_runtime`
  - 负责把“写作任务”送进模型调用链
- `foundation.llm_client`
  - 负责统一模型调用入口
- `foundation.providers.openai_provider`
  - 负责和真实 API 通信

通俗比喻：
`context_package` 像备料，`writer_engine` 像下单，`agent_runtime + llm_client + provider` 像把订单真正送到工厂。

### 写后回写
- `creation.summary_engine`
  - 负责文本摘要
- `creation.structured_summary_engine`
  - 负责结构化摘要
- `memory.summaries`
  - 负责摘要数据保存
- `workflow.write_flow`
  - 负责把“写作 -> 审查 -> 摘要回写”串成一条流程

### 审查
- `review.service_v2`
  - 负责统一调度审查
- `review.continuity_checker`
  - 检查是否承接上一章
- `review.consistency_checker`
  - 检查是否和已知记录冲突
- `review.character_checker`
  - 检查人物是否跑偏
- `review.pacing_checker`
  - 检查近期主线推进密度
- `review.gatekeeper`
  - 根据审查结果决定是否拦截

通俗比喻：
像一组编辑分别看不同问题，最后由总编决定这章能不能过。

### 决策交互
- `decision.service`
  - 负责处理覆盖写入这类裁决
- `decision.question_builder`
  - 负责组织要问用户的问题
- `decision.store`
  - 负责保存裁决记录

### 恢复与查询
- `workflow.resume_flow`
  - 负责恢复信息读取
- `workflow.query_flow`
  - 负责查询入口
- `query.service`
  - 负责整理输出结果

## 3. 用户现在能干什么

这个版本下，用户现在已经可以做这些事：

### 1. 创建一部新小说项目
- 初始化项目目录
- 生成基础状态文件

### 2. 为某一章生成大纲
- 会得到一份完整版大纲
- 也会得到一份给写作流程使用的精简版大纲

### 3. 生成章节草稿
- 系统会读取当前项目状态
- 读取本章精简大纲
- 自动进入写作流程

### 4. 自动生成章节摘要
- 写完后会自动产出文本摘要和结构化摘要

### 5. 让系统进行基础审查
- 至少可以检查章节是否和前文接得上
- 系统也已经具备一致性、人设、节奏检查的框架

### 6. 在覆盖旧章节时做选择
- 可以决定中止还是覆盖

### 7. 查询当前项目状态
- 看项目信息
- 看写作进度
- 看最近任务
- 看快照
- 看决策记录
- 看摘要

### 8. 恢复最近任务现场
- 查看最近一次任务停在哪一步
- 读取对应快照

## 4. 这个版本的定位

这个版本不是最终成品，而是一个已经跑通主链路的工程基线。

它最重要的意义是：

- 骨架已经稳定
- 真实 API 主链路已经验证过
- 后续开发可以从“搭系统”转入“调内容质量”

一句话概括：

这个版本已经证明，这个系统不是停留在文档和空壳阶段，而是已经能真实完成“规划 -> 写作 -> 审查 -> 摘要 -> 查询”这条主流程。
